# Contribuer à Omada for eureka

Tu n'as pas besoin d'être administrateur pour contribuer. Toute personne peut proposer une ressource, une activité, un projet ou une amélioration de la documentation.

## Où contribuer ?

| Tu veux… | Dépôt |
| --- | --- |
| Modifier une règle, un guide, une procédure | [community-handbook](https://github.com/Omada-for-eureka/community-handbook) |
| Ajouter ou corriger une ressource | [resources](https://github.com/Omada-for-eureka/resources) |
| Proposer ou rejoindre un projet | [community-projects](https://github.com/Omada-for-eureka/community-projects) |
| Proposer une activité ou publier un compte rendu | [activities](https://github.com/Omada-for-eureka/activities) |

## Étapes

1. **Ouvrir une Issue** en choisissant le modèle adapté (proposition, documentation, bug…).
2. **Attendre un premier retour** d'un mainteneur si le changement est important.
3. **Créer une branche** depuis `main` (voir [docs/github-guide.md](docs/github-guide.md)) :
   - `docs/nom-du-sujet`, `feat/nom-fonctionnalite`, `fix/nom-correction`, `chore/nom-tache`.
4. **Faire des commits clairs** : `docs: add contribution guide`, `fix: correct broken resource link`…
5. **Ouvrir une Pull Request** en remplissant le modèle et en liant l'Issue (`Closes #12`).
6. **Relecture** par une personne autre que l'auteur lorsque c'est possible.
7. **Fusion** par un mainteneur, puis suppression de la branche.

Si tu n'as pas les droits d'écriture, crée un **fork**, pousse ta branche dessus et ouvre la Pull Request depuis ton fork.

## Règles

- Respecter le [code de conduite](CODE_OF_CONDUCT.md).
- Ne jamais publier de mot de passe, jeton, clé API ou donnée personnelle.
- Respecter les licences et droits d'auteur.
- Une Pull Request = un sujet.
- Les décisions importantes sont discutées dans une Issue avant d'être appliquées (voir [docs/decision-making.md](docs/decision-making.md)).

## Premières contributions

Cherche les Issues étiquetées `good first issue` dans les dépôts de l'organisation.
