# Feuille de route

Le suivi détaillé se fait dans les Issues étiquetées `roadmap` et dans le GitHub Project `Community Operations`.

| Phase | Objectif | Critère d'acceptation |
| --- | --- | --- |
| 0 — Préparation | Nom, mission, fondateurs, périmètre | Les fondateurs approuvent la mission, le nom et le périmètre |
| 1 — Fondation GitHub | Organisation créée, sécurisée, équipes | Permissions conformes à la matrice |
| 2 — Dépôts et documentation | 4 dépôts essentiels documentés | Chaque dépôt explique son utilité et comment contribuer |
| 3 — Collaboration GitHub | Labels, modèles, protection, Project | Un non-admin peut proposer une contribution et suivre son traitement |
| 4 — Discord | Serveur, salons, rôles, modération | Un nouveau membre comprend le serveur et participe aux salons autorisés |
| 5 — Intégration | Notifications GitHub → Discord | Les événements importants arrivent dans le bon salon |
| 6 — Contenu et lancement | Premières ressources, première activité | La communauté accueille ses premiers membres et organise sa première activité |
| 7 — Amélioration | Bilan du premier mois | Liste priorisée d'améliorations disponible |

## Ordre d'exécution

1. Valider la mission, le nom et les fondateurs.
2. Créer et sécuriser l'organisation GitHub.
3. Créer `community-handbook`, `resources`, `community-projects`, `activities`.
4. Ajouter les README, guides et modèles.
5. Configurer les rôles et permissions GitHub.
6. Configurer Issues, Pull Requests, labels et Projects.
7. Tester une contribution réelle.
8. Créer et configurer Discord, puis le tester avec un membre standard.
9. Relier GitHub et Discord.
10. Ajouter les premières ressources.
11. Préparer et réaliser la première activité.
12. Lancer officiellement la communauté.
13. Faire le bilan et prioriser les évolutions.

**Ne pas commencer par le bot ou le site web.**

## Premier mois

- **Semaine 1 :** présentation de la communauté, accueil, présentation de GitHub et Discord, recueil des domaines d'intérêt.
- **Semaine 2 :** premier partage de ressources, premier challenge simple, atelier Git et GitHub.
- **Semaine 3 :** premier Tech Talk, propositions de projets, constitution de petites équipes.
- **Semaine 4 :** présentation des résultats, bilan, recueil des retours, publication de la prochaine feuille de route.

## Phases ultérieures

- `community-bot` : uniquement après identification de besoins réels et répétitifs.
- `community-website` : uniquement après validation des besoins.
