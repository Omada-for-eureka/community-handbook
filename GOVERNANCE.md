# Gouvernance

## Principes de fonctionnement

1. **Ouverture :** tout membre peut proposer une ressource, une activité ou un projet.
2. **Contribution :** les membres peuvent contribuer sans être administrateurs.
3. **Responsabilité :** chaque activité ou projet a un responsable identifié.
4. **Transparence :** les règles, décisions et procédures sont documentées.
5. **Respect :** les échanges restent respectueux et constructifs.
6. **Qualité :** les ressources et contributions sont vérifiées avant intégration.
7. **Continuité :** les connaissances ne dépendent pas d'une seule personne.
8. **Sécurité :** les accès sont limités au besoin réel de chaque rôle.

## Où vivent les informations ?

| Domaine | Plateforme |
| --- | --- |
| Gouvernance, règles, procédures | GitHub (`community-handbook`) |
| Bibliothèque de ressources | GitHub (`resources`) |
| Projets | GitHub (`community-projects` et dépôts dédiés) |
| Activités et comptes rendus | GitHub (`activities`) + Discord |
| Discussions, entraide, annonces | Discord |
| Suivi des tâches | GitHub Projects `Community Operations` |

**Règle :** Discord ne doit pas être l'unique endroit où une connaissance importante est conservée. Décisions, tutoriels, supports et comptes rendus durables sont archivés sur GitHub.

## Rythme de coordination

- Réunion de coordination périodique (fréquence : [À DÉFINIR]).
- Bilan mensuel léger.
- Revue des rôles tous les trois mois.
- Passation documentée lorsqu'un responsable quitte son rôle.

## Continuité

Chaque responsable documente :

- Ce qu'il gère.
- Les opérations régulières.
- Les accès nécessaires, sans publier les secrets.
- Les incidents connus.
- Les procédures de remplacement.
- Les décisions importantes.

## Modification de ce document

Toute modification importante de l'architecture, des rôles ou des règles est discutée dans une Issue, validée par les fondateurs, puis appliquée par Pull Request.
