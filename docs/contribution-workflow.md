# Parcours d'une contribution

## Cas général

```text
Idée ou problème
      |
      v
Issue (modèle adapté)  --> label status: triage
      |
      v
Triage par un mainteneur (labels, priorité, responsable)
      |
      v
Branche + commits
      |
      v
Pull Request (modèle rempli, "Closes #N")
      |
      v
Relecture (autre personne que l'auteur si possible)
      |
      v
Fusion dans main + suppression de la branche
      |
      v
Annonce dans Discord si pertinent
```

## Cas d'une ressource

```text
Membre découvre une ressource
          |
          v
Partage le lien dans Discord ou ouvre une Issue
          |
          v
Un mainteneur vérifie le lien et les informations
          |
          v
Le contributeur ou le mainteneur prépare la fiche
          |
          v
Pull Request -> Relecture et validation -> Fusion dans resources
          |
          v
Annonce dans Discord si pertinent
```

Critères de validation d'une ressource :

- Lien fonctionnel.
- Source identifiable.
- Description utile.
- Catégorie correcte.
- Niveau et langue renseignés lorsque pertinents.
- Respect des droits d'auteur.
- Absence de secret ou de donnée privée.

## Délais

Les mainteneurs sont bénévoles : il n'y a pas de délai garanti. Une Issue sans réponse après une semaine peut être relancée poliment dans `#maintenance-github` ou en commentaire.
